## 0. 一句话定义

一个**纯本地、不联网、无账号、无广告**的手机 App，把日常最常做的四件事——习惯打卡、记账、备忘录、待办——收在一个地方；并配一张**桌面小卡片**，习惯和待办不用打开 App 就能点掉。

---

## 1. 目标与边界

| 项 | 决策 | 理由 / 代价 |
| --- | --- | --- |
| 平台 | 本期只做手机端，原生 Android（Kotlin） | 用户明确选择。代价：**二期电脑端无法复用这套代码**，需另做 Web/桌面端或届时改跨平台 |
| 二期 | 电脑端、多端同步 | 后置。当前只预留同步字段，不接云 |
| 范围策略 | **四块全上，但每块做薄** | 先拿到四块都能用的成品找感觉，而不是先做透一块或一次做全量 |
| 交付 | 直接建工程并编译出 APK | 源码留在工作区便于继续改；不装 Android Studio 也能命令行构建 |
| 联网 | 完全不联网 | 单用户、纯本地；权限最小化 |

### 不做（明确排除）

不接云同步、不加账号体系、不加广告/会员墙、不做理财导流、不做社交/社区、不做首页信息流、不引第三方设计依赖、不加密数据库、不实现生物锁（仅预留接口）。

## 2. 用户与场景

单用户自用。典型一天：

1. 早上看一眼桌面小卡片 → 点掉「喝水」「早读」和两条待办，全程不打开 App。
2. 中午吃饭 → 打开 App 记一笔，选分类、输金额、保存，两步完成。
3. 想到什么 → 备忘录一行输入，带 `#标签`。
4. 晚上 → 今日习惯页看完成进度，顺手给忘记的日子补卡。

## 4. 功能规格

### 4.1 习惯打卡（首页）

**实体字段**

| 字段 | 说明 |
| --- | --- |
| 名称 | 纯文本 |
| 周期 | 每天 / 每周几（多选，周一为周首） |
| 颜色 | 用于热力图与列表标识 |
| 完成记录 | 按「习惯 + 日期」唯一，一天最多一条 |

**v1 功能**

- 今日习惯列表，**点一下圆圈即完成**；App 内再点一下可取消（可恢复）。
- 统计：当前连续天数、最长连续天数、完成率。
- **月历热力图**：按当月每天完成情况着色，用主色透明度分级；周一起始。
- **补卡 / 取消**：点月历上过去任意一天可补卡或取消，连续天数**按真实记录重算**。
- 增 / 改 / 删（软删）。

**v2（不做）**：可量化目标、提醒通知、打卡图片。

**关键规则**：连续天数按「应做日序列」的相邻关系判断，而不是 `date + 1 天`。例如「每周一三五」的习惯，周一 → 上一个周五应视为连续，跨周末不断链。

---

### 4.2 记账

**实体字段**：类型（收入/支出）、金额、分类、备注、日期。

**v1 功能**

- **两步记一笔**：默认支出页签 → 选分类 → 数字键盘输金额 → 备注可选 → 保存。
- **分类选择器与数字键盘同屏可见**（重要，见 §9 反面教训）。
- 一套默认分类：支出约 10 类、收入 3–4 类；图标与颜色可再次编辑。
- 增 / 改 / 删。
- 统计：**月度总额 / 收入 / 结余 + 分类占比环形图**；图表可交互（点分段显金额占比）。
- 单币种 ¥，不做二级分类与标签。

**v2（不做）**：预算/超支、周期性收支、多账户与转账。

**关键规则**：金额用 `Long` 存**分**，绝不用浮点；月度汇总走 Room `GROUP BY` SQL 聚合，不把明细全捞进内存再算。

---

### 4.3 备忘录

**v1 功能**：纯文本、一行输入、`#标签`、搜索、置顶、增 / 改 / 删（软删）。

**v2（不做）**：富文本/图片、文件夹/回收站。

**设计取向**：学 flomo——放弃文件夹与复杂分类，把记录成本降到最低。无标题栏，输入即保存。

---

### 4.4 待办

**v1 功能**

- 标题、勾选完成、**截止时间**。
- **「今天」视图**（默认）+ 全部 + 已完成 三个分段。
- **逾期标红**。
- **已完成可恢复**：Room 里 `done` 只是状态标记，不删行；「已完成」列表一键取消勾选恢复。
- **自然语言日期最小集**：输入「明早十点开会」自动识别为截止时间（最小集：今天/明天/后天/周X/X点X分）。
- 增 / 改 / 删。

**v2（不做）**：子任务、重复、优先级。

### 4.5 桌面小卡片（App Widget）★ 一期重点

| 项 | 决策 |
| --- | --- |
| 内容 | **习惯 + 待办同在一张卡**：上半区今日习惯，下半区未完成待办 |
| 勾选 | **点一下即写库完成并从卡片消失**，无二次确认、卡片上不塞撤销 UI |
| 恢复 | **App 内可恢复**——`done` 只标状态不删行，进 App 的「已完成」列表一键取消勾选（定稿时把最初的「不可撤销」改掉了） |
| 刷新 | App 内任何数据改动**主动通知小组件刷新**；每天 0 点自动翻到新一天 |
| 打开 App | 点标题 / 空白处；卡片上不做快速新增 |
| 尺寸 | Jetpack Glance `SizeMode.Responsive` 可缩放，默认约 4×2 格 |
| 条数 | 最多显示 5~6 条，超出显示「还有 N 项」 |
| 实现 | Jetpack Glance 1.1.1，`minSdk 31`（Android 12+） |

**交互细节（借鉴 omarchy-todoist）**：点掉时先短暂划线变暗再消失，让点击读作「完成」而不是「凭空消失」。

**技术要点（已用 `javap` 核对 Glance 1.1.1 真实签名）**

- `GlanceAppWidget.provideGlance()` 是 suspend，内部 `provideContent { ... }`；数据源用 Room `Flow.collectAsState`。
- 点击写库：`actionRunCallback<T>()` + `ActionParameters.Key` 传 `itemId`；`ActionCallback` 必须 **public + 无参构造**（框架反射实例化），`onAction` 是 suspend，可直接调 Room suspend DAO，**不要 `launch{}` 后立刻返回**。
- 写后**必须显式** `ImprintWidget().update(context, glanceId)`；不能指望 Flow 自动重组。App 内改数据的刷新统一收口在 **Repository 层**（`updateAll(context)`），不要散落在 ViewModel 否则后台入口漏刷。
- 「勾掉并消失」靠**查询过滤本身**（`WHERE done = 0 AND date = 今日`），不是内存 state 假装隐藏——卡片随时会被系统重建，内存隐藏会「复活」。
- 0 点翻篇：`provideGlance` 每次按 `LocalDate.now()` 重算今日 + 接收 `ACTION_DATE_CHANGED` + 对齐次日 0 点的兜底任务。
- `SizeMode.Responsive` + `LazyColumn.items` 的 `itemId`（跨更新保持滚动位置）+ 复合按钮 + 资源 ID 以缩小 RemoteViews。

### 4.6 本地导出 / 备份恢复

一期顺带上，且**免费、无需登录、不设笔数限制、不设会员墙**：

- 导出：CSV（记账/习惯/待办）+ JSON（全量备份，含备忘录标签）。
- 恢复：从 JSON 备份导入。
- 走系统文件选择器（SAF），不申请存储权限。

> 这一条是硬要求：纯本地 App 若没有导出/恢复，卸载即数据全丢；商业产品里「导出锁会员」和「停服删数据」是最集中的两类差评（见 §9）。

## 5. 数据模型

Room，纯本地，单用户。所有表带**同步预留字段**：

| 公共字段 | 用途 |
| --- | --- |
| `updated_at` | 将来增量同步 |
| `deleted_at` | 软删，保留历史与统计口径 |
| `device_id` | 将来冲突归并 |

**表清单**

| 表 | 要点 |
| --- | --- |
| `habits` | 名称、周期（周几列表）、颜色、`is_active` |
| `habit_completions` | `habit_id` + `date`（`yyyy-MM-dd` 本地日字符串）**联合唯一索引**；外键 `ON DELETE CASCADE` |
| `transactions` | 类型、`amount_cents: Long`、分类、备注、日期 |
| `categories` | 默认分类；图标/颜色可编辑；预留分类预算字段 |
| `notes` | 正文、标签、置顶 |
| `todos` | 标题、`done`、`due_at` |

**约束**：从一开始就定好 FK CASCADE + 索引 + 联合唯一索引 + `exportSchema=true` + 显式 Migration。业务日期一律用本地 `LocalDate` 的 ISO 字符串，天然避开 DST；只有「操作时刻」才用 UTC epoch。

## 6. 关键业务规则汇总

| # | 规则 |
| --- | --- |
| 1 | 金额 `Long` 存分，聚合走 SQL `GROUP BY` |
| 2 | 日期业务键 = 本地 `yyyy-MM-dd`，时区 `Asia/Shanghai`，周起始**周一** |
| 3 | 连续天数 / 最长连续 / 完成率**全部派生，不落库**；任何完成记录变更触发全量重算 |
| 4 | 最长连续按「应做日序列」相邻判断，不用 `plusDays(1)` |
| 5 | 删除一律软删（`deleted_at`），保留统计口径 |
| 6 | 完成状态 `done` 只标不删行，因此 App 内随时可恢复 |
| 7 | 卡片勾选 = 一次性写入 + 显式 `update()`；卡片不提供撤销 |
| 8 | 单币种 ¥、一套默认分类、无二级分类 |

| 二期功能 | 提醒通知、可量化目标、预算、周期收支、多账户、子任务、重复、优先级、富文本、文件夹/回收站、云同步、生物锁 |
